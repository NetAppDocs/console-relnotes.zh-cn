[[kubernetes-workloads-enhancements]]
=== Kubernetes 工作负载增强功能

在本版本中，NetApp Backup and Recovery 为 Kubernetes 工作负载引入了以下增强功能：

* *Amazon FSx for NetApp ONTAP 支持磁盘到磁盘备份架构*：您现在可以在相同的 AWS 区域或不同的 AWS 区域中创建 Kubernetes 保护策略，该策略使用磁盘到磁盘备份架构，其中 Amazon FSx for NetApp ONTAP 作为主存储，另一个 FSx for NetApp ONTAP 文件系统作为辅助存储。您还可以将 Cloud Volumes ONTAP 作为主存储，将 FSx for NetApp ONTAP 作为辅助存储。
* *修复了 qtree 还原问题*：ontap-nas-economy 卷还原以前还原的 qtree 目录的所有者和权限不正确。此问题已在此版本中得到解决。


有关创建 Kubernetes 保护策略的详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-policies-kubernetes-create.html["在 NetApp Backup and Recovery 中创建和管理 Kubernetes 备份策略"^]。

要了解有关保护 Kubernetes 工作负载的详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["了解如何通过 NetApp Backup and Recovery 保护 Kubernetes 工作负载"^]。



[[ontap-volumes-workloads-enhancements]]
=== ONTAP Volumes 工作负载增强

在本版本中，NetApp Backup and Recovery 为 ONTAP 卷工作负载引入了以下增强功能：

* *还原界面改进*：ONTAP 卷的还原向导采用了全新的布局并改进了导航：
+
** *改进的选择表*：选择表一次显示更多行和列。还原屏幕使用精细的间距和面包屑，因此您可以查看自己在工作流中的位置。
** *分步导航*：*下一步*和*继续*按钮功能已得到改进，因此您不会不小心跳到下一个主要步骤。*上一步*按钮将返回到您完成的最后一个屏幕，并保留您之前的选择，因此您无需重新启动该步骤。
** *选择源卷时的更多详细信息*：卷列表现在显示卷类型、卷样式、SnapLock 类型、现有保护和保护运行状况。现有保护列更宽，因此您可以看到所有保护指标（快照、复制和备份）。


* *支持保护 Azure 中国区域中托管的卷*：您现在可以将 ONTAP 卷备份到 Azure 中国（世纪互联）中的 Azure Blob 存储。此支持适用于 Cloud Volumes ONTAP 和本地 ONTAP 系统。商业 Azure 和 Azure 政府区域保持不变。


要了解有关保护 ONTAP Volumes 工作负载的详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["了解使用 NetApp Backup and Recovery 的 ONTAP 卷保护"^]。
