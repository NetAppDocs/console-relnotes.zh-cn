=== Workload Factory



==== Workload Factory 管理增强功能



===== 检查和刷新自定义仪表板数据

现在，您可以查看上次更新自定义控制面板指标的时间，并手动刷新这些指标。将鼠标悬停在*刷新数据*上以查看上次更新的日期和时间。

选择*刷新数据*以开始新的扫描。横幅将确认扫描已开始，并且该按钮将被禁用，直到扫描完成。

有新数据可用时，请在通知横幅中选择*立即加载*以更新控制面板。

*刷新数据*和*立即加载*均会在 Tracker 中创建数据收集事件。

link:https://docs.netapp.com/us-en/data-services-workloads/admin/manage-custom-dashboards-fsx.html#refresh-dashboard-data["了解如何刷新自定义仪表板数据"]



===== 指定自定义仪表板的区域

如果您的请求未包含区域，自定义控制面板现在会要求您选择一个或多个区域。控制面板数据仅限于您选择的区域。

link:https://docs.netapp.com/us-en/data-services-workloads/admin/create-custom-dashboard-fsx.html["了解如何创建自定义仪表板"]



===== FSx for ONTAP 链接创建的 IAM 策略

用于创建链接的 CloudFormation 模板和 Terraform 代码现在使用 IAM 策略而不是内联 Lambda 权限。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-storage/create-link.html["了解如何创建链接"]



===== 审核和跟踪 AI 代理操作

您现在可以使用 Tracker 查看 AI 代理设置的更改，并在读/写模式下查看每个审批请求，包括代理的问题和用户的答案。

通过 Workload Factory API 进行的资源更改由执行该操作的 Workload Factory 服务记录。

link:https://docs.netapp.com/us-en/data-services-workloads/admin/learn-agent.html["了解审核和跟踪代理操作的相关信息"]



==== Amazon FSx for NetApp ONTAP 增强功能



===== 启动程序组图增强功能

在“管理客户端访问权限”页面上显示块设备启动器组的图表现在包括主机的更多详细信息。当您将鼠标悬停在图表中的主机上时，将显示主机详细信息，包括主机名、实例 ID、工作负载类型、区域和 iSCSI 限定名称（IQN）。



===== 针对架构完善的问题的电子邮件增强功能

新的电子邮件设计为 Workload Factory 检测到的配置问题提供了更多详细信息和上下文。该电子邮件包括已分析的资源数量、存在警告或严重问题的资源数量，以及这些问题是什么。该电子邮件还链接到 FSx for ONTAP 架构完善的控制面板，以便您可以立即解决问题。



===== 精心设计的仪表板增强功能



====== 支持选定的配置检查

您可以对选定配置手动运行分析，以便仅分析您感兴趣的配置并减少等待时间。



====== 精心设计的分析中的新建议

Workload Factory 现在在 FSx for ONTAP 文件系统的良好架构分析中包含以下配置：

对于存储工作负载：

* *将主机连接到故障转移节点*：检查主机是否连接到主动-被动 FSx for ONTAP 文件系统中的故障转移节点，以确保可靠性。
* *将主机连接到首选节点*：检查主机是否使用首选节点连接到其块设备，以提高性能效率。
* *ARP/AI 多设备检测差距*：当卷仅连接了一个块设备时，ARP/AI 可提供全面的保护覆盖。如果卷连接了多个块设备，Workload Factory 会将这些块设备移动到新卷，以便每个卷只有一个块设备。
* *克隆清理*：检查是否有任何超过 30 天的卷克隆可以删除，以优化存储使用并降低成本。
* *将 igroup OS 与主机匹配*：检查启动器组（igroup）的操作系统是否与主机的操作系统匹配，以防止 I/O 或性能问题。


对于 Kubernetes 工作负载：

* *QoS 配置*：检查 Kubernetes 持久卷是否受到 ONTAP QoS 策略的保护，以提高性能效率。
* *专用 Kubernetes 存储虚拟机*：检查文件系统是否正在为 Kubernetes 工作负载使用专用存储虚拟机，以提高隔离度并简化存储管理。
* *专用 Kubernetes 导出策略*：检查每个 Kubernetes 持久卷是否具有仅允许从集群的工作节点访问的专用导出策略。
* *Kubernetes iSCSI 后端的双向 CHAP*：检查 Trident iSCSI 后端是否启用了双向 CHAP 身份验证以确保安全。
* *在应用程序存储 VM 上禁用 `showmount`*：检查是否在应用程序存储 VM 上禁用了 `showmount`，以防止客户端列出其无法访问的导出。


对于数据库工作负载：

* *SAP HANA 快照策略*：检查 SAP HANA 卷的快照策略是否设置为“无”，以降低存储成本并提高活动数据库数据的性能。
* *MySQL 快照策略*：检查 MySQL 卷的快照策略是否设置为“None”，以降低存储成本并提高活动数据库数据的性能。
* *PostgreSQL 快照策略*：检查 PostgreSQL 卷的快照策略是否设置为“None”，以降低存储成本并提高活动数据库数据的性能。

您可以在架构完善的仪表板中查看某些未优化配置的当前值和推荐值。这可让您在进行修复之前了解推荐值。

* 冷数据分层
* Snapshot 策略
* 固态硬盘容量余量




===== 成本改进



====== 成本预测和见解

现在，您可以使用成本预测功能预测 FSx for ONTAP 文件系统的成本。这有助于您规划预算并有效优化资源。您还可以查看有关成本和使用模式的见解，以确定成本优化的机会。



====== AWS 成本和使用情况报告（CUR）

Workload Factory 现在使用 AWS Cost and Usage Reports（CUR）而不是 AWS Cost Explorer 来提供交付给客户拥有的 S3 存储桶的详细计费记录。CUR 提供了更好的成本粒度，并作为高级 FinOps、内部计费和成本分配用例的基础。



===== Storage VM 迁移改进

Workload Factory 在用户界面中为迁移存储虚拟机提供增强的指导。这包括分步说明以及在将迁移提交到生产环境之前进行测试运行。

link:fsx-storage/create-replication.html["详细了解存储虚拟机迁移"]



===== 复制滞后电子邮件通知改进

当发生大量相关复制延迟事件时，Workload Factory 会自动将其合并为一封电子邮件通知，以免您收到过多通知。



===== 自动容量管理增强

现在，您可以在要求 Workload Factory 自动管理您的容量之前，打开自动容量管理通知以试用此功能。当您的文件系统容量不足时，您将收到通知。



===== 精心设计的仪表板中包含的数据库配置

精心设计的仪表板现在包含针对您的数据库配置的建议，使您能够根据最佳实践评估和优化设置。仪表板中包含的首批配置包括：

* 冷数据分层
* 存储效率
* Snapshot 策略
* 固态硬盘容量余量
* 块设备空间管理
* OS 类型
* 将块设备操作系统类型与主机匹配
* 非活动的数据块设备（LUN）
* 数据文件（.mdf）放置
* 日志文件（.ldf）放置
* 多路径 I/O 状态
* 多路径 I/O 超时
* 集群仲裁
* 计算资源合理调整


在 Workload Factory 控制台中选择主菜单，然后选择 *Well-architected* 以查找架构完善的仪表板。

您可以在 Workload Factory 中再次对卷运行延迟分析，以便在调查或进行更改后刷新结果。选择 *再次运行分析* 以开始新的分析并更新结果。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-eda/task-analyze-latency-issues.html["了解如何分析延迟问题"]

=== AI Data Engine



==== AI Data Engine 1.3

AI Data Engine 是一项元数据智能服务，通过 NetApp Console 进行管理，可扫描您连接的系统，构建元数据目录，并为您提供可见性和工具，以大规模优化存储和治理数据。您可以将 AI Data Engine 部署为 https://docs.netapp.com/us-en/ai-data-engine/deploy/deployment-overview.html["AIDE 单节点部署"^]，或者如果您的环境需要大规模基于 Kubernetes 的高可用性，则可以将其部署为 AIDE 多节点部署。

AI Data Engine 1.3 是第一个通用（GA）版本。

.部署和连接您的数据
https://docs.netapp.com/us-en/ai-data-engine/deploy/deployment-overview.html["以您的环境所需的规模进行部署"^]:: 选择 AIDE 单节点部署以便在单个虚拟机上快速启动，或者在您自己的 Kubernetes 集群上选择 AIDE 多节点部署以实现高可用性和更大规模。如果您的环境需要代理才能访问互联网， https://docs.netapp.com/us-en/ai-data-engine/deploy/configure-proxy.html["了解 AIDE 的代理"^]并使用代理进行部署。

https://docs.netapp.com/us-en/ai-data-engine/administer/monitor-deployment-health.html["保持扫描正常"^]:: 监控部署的运行状况，以确定可能中断扫描的问题，并收集解决这些问题所需的详细信息。


.优化存储并调查您的数据
https://docs.netapp.com/us-en/ai-data-engine/investigate/understand-dashboard.html["恢复存储容量"^]:: 根据您配置的阈值，识别连接系统中的冷数据、过时数据和重复数据，并查看哪些系统和数据所有者拥有最高浓度的此类数据。

https://docs.netapp.com/us-en/ai-data-engine/investigate/investigate-data.html["消除重复数据"^]:: 查找在连接的系统中具有重复副本的文件。按重复项属性或文件哈希过滤以查看重复组，然后清理重复副本。

=== 备份和恢复



==== Kubernetes 工作负载增强功能

在本版本中，NetApp Backup and Recovery 为 Kubernetes 工作负载引入了以下增强功能：

* *Trident Protect 26.10*：此版本包括 Trident Protect 26.10。
* *ontap-nas-economy 和 ontap-san-economy 驱动程序支持*：您现在可以保护由 NetApp Trident `ontap-nas-economy` 驱动程序（Qtrees）和 `ontap-san-economy` 驱动程序（LUNs）配置的持久卷声明（PVCs）。当您使用 economy 驱动程序保护 PVC 时，整个底层 FlexVol 或 LUN 都会受到保护。您可以从这些备份还原单个 PVC。
* *Kubernetes 感知警报*：警报现在每个 Kubernetes 应用程序发送一次，而不是每个卷发送一次。
* *卷组快照支持*：现在可以在定义 Kubernetes 应用程序时创建卷组。卷组使您能够以崩溃一致性集的形式为多个卷一起创建快照，从而确保组中所有卷的数据一致性。
* *S3 兼容的对象存储支持*：您现在可以通过添加备份目标凭据和配置保护策略，将 Kubernetes 应用程序资源和数据备份到 S3 兼容的对象存储中。

==== Azure 中的 Cloud Volumes ONTAP 9.19.1

https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-new.html["Cloud Volumes ONTAP 9.19.1 发行说明"^]



==== 适用于 Cloud Volumes ONTAP 的 Azure 主机加密

从 Cloud Volumes ONTAP 9.19.1 GA 开始，对于满足先决条件的新 Azure 单节点和高可用性（HA）部署，默认情况下会在主机上启用 Azure 加密。此功能会在数据写入主机和从主机读取时，对托管 VM 的物理服务器上的数据进行加密，包括临时磁盘和相关的主机级缓存。

在 Azure 中部署 Cloud Volumes ONTAP 之前，请确认您的环境满足以下先决条件：

* 已为您的 Azure 订阅注册了 `EncryptionAtHost`功能。请参阅 https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli["Microsoft 文档：在主机上启用加密"^]。
* 所选 VM 实例类型支持在您的 Azure 区域的主机上进行加密。请参阅 https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli#finding-supported-vm-sizes["Microsoft 文档：查找支持的 VM 大小"^]。


请注意以下几点：

* 无需额外配置。
* 如果不满足这些先决条件，则不会为 Cloud Volumes ONTAP 部署启用主机上的 Azure 加密。
* 主机加密仅适用于 Azure，不适用于 AWS 或 Google Cloud。


Microsoft 文档： https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal["使用 Azure 门户通过主机加密启用端到端加密"^]



==== Azure 和 Google Cloud 中 Cloud Volumes ONTAP 集群上的后端网络加密

Cloud Volumes ONTAP 9.19.1 及更高版本支持 Azure 和 Google Cloud 中 HA 配置的后端群集网络加密。

启用集群网络加密可能会影响集群性能。在启用此功能之前，请谨慎操作，并验证您的环境是否可以承受额外的开销。

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enable-cluster-encryption.html["在 Cloud Volumes ONTAP 集群上启用后端网络加密"^]



==== 能够减少 Azure 计划维护期间的中断

在计划维护期间，Azure 可以短暂暂停 Cloud Volumes ONTAP HA 对中的虚拟机。ONTAP 可能会将暂停解释为节点中断，并将存储操作移至伙伴节点，然后在 VM 恢复时将其移回（接管和交还）。即使没有节点故障，此过程也可能中断活动的客户端连接。

使用 Cloud Volumes ONTAP 9.19.1 及更高版本，您可以启用一项可选设置，允许 HA 对在 Azure 计划维护冻结期间继续运行，而无需自动启动接管和交还。


NOTE: 此功能在 Cloud Volumes ONTAP 9.19.1 中作为公开预览版提供。

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-azure-prevent-freeze.html["防止在 Azure 维护期间 Cloud Volumes ONTAP HA 对发生中断"^]
