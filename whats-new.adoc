=== 勒索软件抵御能力



==== 自动响应用户活动警报

Ransomware Resilience 现在支持在生成用户活动警报时自动创建快照和阻止用户。通过自动响应，您可以在生成警告后立即阻止用户，并创建快照进行恢复，从而无需手动干预即可更快地响应。

有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-automate-user-activity.html["自动响应用户活动警报"^]。



=== 数字顾问



==== 运行状况检查 GraphQL 迁移和数据准确性改进

运行状况检查模块得到了增强，提高了数据准确性和符合货币标准的版本建议。作为此版本的一部分，它已从公共 API 迁移到 GraphQL，提供了改进的性能、灵活的查询和长期支持。



===== 建议使用的软件

运行状况检查模块中的推荐软件增强功能现在提供了更准确和一致的数据。

* 固件版本显示下的磁盘架和驱动器计数显示每个系统的准确值，不再包括 HA 对计数。
* 最低和最新版本建议现在根据有效集群版本在集群级别进行计算，符合货币标准——以前，这些建议是在节点级别计算的。

==== Kubernetes 工作负载增强功能

在此版本中，Kubernetes 工作负载引入了以下增强功能：

=== 灾难恢复



==== Kubernetes 更新

灾难恢复针对基于 Kubernetes 的工作负载引入了以下更改：



===== 测试 Kubernetes 工作负载的故障转移支持

灾难恢复现在支持测试 Kubernetes 工作负载的故障转移过程。测试故障转移允许您验证灾难恢复计划。完成测试后，您可以清理测试故障转移，以便系统自动清理测试资源，以减少开销并确保环境的一致性。

有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html#test-the-failover-process["测试故障转移过程"^]。



===== 计划的测试故障转移

您现在可以通过安排测试故障转移来自动执行灾难恢复测试。您可以设置定期测试故障转移的时间表，以连续验证恢复计划，而无需人工干预，有助于保持对恢复目标的信心并满足合规性要求。

有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/manage.html#manage-replication-plans["管理复制计划"^]。



===== Kubernetes 工作负载的计划发现

使用定时发现，您可以控制 Disaster Recovery 扫描新 Kubernetes 工作负载的频率。您可以配置发现间隔以与操作节奏保持一致，从而减少不必要的系统开销，同时确保及时检测和保护新的工作负载。

有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/sites-add.html#edit-the-site-and-customize-the-discovery-schedule["自定义发现计划"^]。



==== VMware 更新



===== 空数据存储的保护

灾难恢复现在允许为不包含任何虚拟机 (VM) 的数据存储配置保护。随后添加到数据存储的任何 VM 都会被灾难恢复自动检测到，此时您必须提供 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/sites-add.html#add-subnet-mapping-for-a-vcenter-site["映射信息"^]。

将空数据存储区添加到保护计划时，必须在执行故障切换之前从保护计划中删除该数据存储区，或执行强制故障切换。有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["故障转移到远程站点"^]。



===== 将先前排除的数据存储还原到保护计划

以前排除在保护范围之外的数据存储区现在可以重新包括在内。随着时间的推移，在管理和更新灾难恢复配置时，此增强功能提供了更大的灵活性。

有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/manage.html["管理站点、资源组和复制计划"^]。



===== 基于 VMFS 的数据存储更快的故障切换

Disaster Recovery 提高了基于 VMFS 的数据存储的故障转移性能。Host Bus Adapter (HBA) 重新扫描和数据存储装载操作现在可以并行执行，从而减少总体故障转移时间，并最大限度地减少恢复事件期间的停机时间。

有关故障转移的详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["使用灾难恢复进行故障切换"^]。



=== 勒索软件抵御能力



==== 增强保护策略的灵活性

Ransomware Resilience 现在为选择勒索软件检测策略提供了更大的灵活性。以前，所有勒索软件保护策略都必须包括加密检测。现在，您可以仅使用用户行为检测来启用勒索软件保护策略。

保护策略仍然可以包括加密检测_和_可疑用户行为检测。阻止文件扩展名也可以添加到任何保护策略中。

如果禁用现有策略的部分保护策略，则在策略的上一次迭代下创建的任何现有警报只能标记为"已解决"而不是"已忽略"。例如，如果您有一个保护策略，其中包括加密检测和可疑用户行为，但您禁用了加密检测，则只能解决该工作负载的现有加密警报。

有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-use-protect.html["使用 NetApp Ransomware Resilience 保护策略保护工作负载"^]。



==== SOAR 战术手册增强功能

Ransomware Resilience SOAR 攻略现在可在您阻止用户或使卷脱机后提供补救步骤。如果操作被认为不是勒索软件威胁，您现在可以将卷恢复联机并取消阻止用户。

link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/reference-soar.html["整合 SOAR 攻略"^].



=== Cloud Volumes ONTAP



==== 支持 AWS 中 Cloud Volumes ONTAP 的新 EC2 实例

Cloud Volumes ONTAP 9.16.1 及更高版本支持 M6id 和 M6idn EC2 实例系列，用于 AWS 中的新建和现有单节点和高可用性 (HA) 对部署。与第 5 代通用系统相比，这些第 6 代实例具有更快的处理能力、更强的网络功能和更高的性能。

* *M6id 实例*：通过高速、低延迟的本地 NVMe 存储提供计算和内存的平衡。所有 M6id 实例大小都支持 Flash Cache。这些实例非常适合数据记录和媒体处理等工作负载。
* *M6idn 实例*：提供与 M6id 实例相同的本地 NVMe 存储功能。所有 M6idn 实例大小都支持 Flash Cache。


我们不建议使用较小尺寸的 m6id.xlarge、m6id.2xlarge、m6idn.xlarge 和 m6idn.2xlarge 实例类型进行高性能或内存密集型工作负载。对于这些工作负载，请使用具有更高核心计数和更大内存的实例类型。

有关详细信息，请参阅 https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-configs-aws.html["AWS 中支持的 Cloud Volumes ONTAP 配置"^]。

=== Cloud Volumes ONTAP



==== AWS 中 Cloud Volumes ONTAP 和数据服务的灵活计费

NetApp 为您在 AWS 中的 Cloud Volumes ONTAP 订阅提供了增强的计费选项，让您可以更好地控制如何支付 Cloud Volumes ONTAP 容量和 NetApp 数据服务（如 NetApp Backup and Recovery）的费用。以前，所有 Cloud Volumes ONTAP 和数据服务的使用都是通过 AWS 市场中的 NetApp Intelligent Services (NIS) 列表一起计费的。

由于 AWS 企业折扣计划 (EDP) 的变化，NetApp 在 AWS 市场中引入了独立的 Cloud Volumes ONTAP 订阅，允许您将 Cloud Volumes ONTAP 容量的计费与数据服务分开。这种分离使您可以更灵活地管理 EDP 积分和成本。NetApp 建议使用独立订阅来更好地管理 Cloud Volumes ONTAP 使用情况的成本，同时在 2026 年 7 月 31 日 EDP 要求生效后继续使用 NIS 订阅进行数据服务计费。

AWS 中的独立 Cloud Volumes ONTAP 订阅仅支持基于容量的有效 Essentials 或 Freemium 许可证包。不支持 Professional 包。您可以选择最适合您需求的账单方式：

* *独立 Cloud Volumes ONTAP 订阅（推荐）*：通过 AWS 市场中的独立订阅支付您的 Cloud Volumes ONTAP 使用费用，同时继续通过 NIS 订阅收取数据服务费用。对于在 NetApp Console 中同时拥有与其 AWS 帐户相关联的独立订阅和 NIS 订阅的大多数客户，这是推荐的选项。
* *组合 NIS 订阅*：通过现有的 NIS 列表同时支付 Cloud Volumes ONTAP 和数据服务。组合方法适用于在 NetApp Console 中仅与其 AWS 帐户关联的 NIS 订阅的现有客户。但是，NetApp 建议您为 Cloud Volumes ONTAP 使用量设置计费首选项，并切换到独立订阅以更好地管理成本。


根据您的订阅类型，您将获得以下方案：

.仅限独立订阅（新客户）
如果您在 NetApp Console 中仅有一个与您的 AWS 账户关联的独立 AWS 订阅，并且没有 NIS 订阅，则可以在部署期间仅选择 Essentials 许可证包。您无法使用数据服务*备份和恢复*选项。

.独立订阅和 NIS 订阅（现有客户）
如果您有与 AWS 账户关联的 NIS 和独立订阅，并且尚未通过 NetApp Console 中的*计费首选项*选项卡设置计费首选项，则默认情况下，Cloud Volumes ONTAP 的使用将继续通过 NIS 计费。这也是运行 Professional 包的任何 Cloud Volumes ONTAP 实例的默认值，因为独立列表不支持 Professional。您可以设置计费首选项，并选择如何对每项服务计费：

* 将独立订阅设置为 Cloud Volumes ONTAP（使用 Essentials 包）的首选计费账户。如果您只有 Professional 包，则可以将其转换为 Essentials 包，并通过设置计费首选项对您的 Cloud Volumes ONTAP 使用量收费。我们推荐这种方法，因为它可以帮助您更有效地管理 Cloud Volumes ONTAP EDP 积分。
* 使用 NIS 订阅进行计费数据服务，或通过 Professional 包使用 Cloud Volumes ONTAP。在部署期间，启用 *Backup and Recovery* 数据服务，并选择 Professional 许可证包以通过 NIS 订阅向数据服务收费。


.仅限 NIS 订阅（现有客户）
如果您是拥有与 AWS 帐户关联的 NIS 订阅的现有客户，则适用此规则。您可以继续像现在一样同时计费 Cloud Volumes ONTAP 和数据服务。但是，NetApp 建议切换到独立订阅方法，以便更好地管理您的 Cloud Volumes ONTAP 使用情况：

* 订阅 AWS 门户上的新独立列表。
* 将独立订阅链接到您的 AWS 帐户。
* 使用 Essentials 包将计费首选项设置为 Cloud Volumes ONTAP 使用的独立订阅。
* （如适用）将您的 Professional 套餐转换为 Essentials 套餐并设置账单首选项。
* 通过您的 NIS 订阅继续计费数据服务。



NOTE: 当您使用多种订阅类型或在房源之间迁移时，不会出现重复的计量。

* *将文件还原到 Linux VM*：您现在可以将 VM 文件和文件夹还原到 Linux VM。有关详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-vmware-restore-guest-files-and-folders-from-vmdks.html["还原文件和文件夹"]。
* *还原文件和文件夹时支持代理 VM* - 当您不希望将虚拟磁盘附加到原始 VM 时，现在可以使用代理 VM 从虚拟磁盘还原文件和文件夹。有关详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-vmware-restore-guest-files-and-folders-from-vmdks.html["还原文件和文件夹"]。
* *递归文件和文件夹搜索* - 您现在可以搜索整个虚拟磁盘以查找特定文件或文件夹。有关详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-vmware-restore-guest-files-and-folders-from-vmdks.html["还原文件和文件夹"]。
* *改进的作业处理*：NetApp Backup and Recovery 现在可以更有效地同时处理多个作业。


要了解有关保护 VMware 工作负载的详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-vmware-protect-overview.html["保护 VMware 工作负载概述"]。

=== 勒索软件抵御能力



==== 清理还原

Ransomware Resilience 现在支持 clean restores，这是一种新的恢复选项，可帮助您快速轻松地从勒索软件攻击中恢复。Clean restores 提供指导性工作流程，可识别最佳还原点以启动和运行您的工作负载，同时最大限度地减少停机时间。Clean restore 中的工作流程还提供对数据的文件级见解，确保您可以还原无恶意软件的工作负载，从而防止再次感染并最大限度地减少数据丢失。

要了解支持的配置以及如何配置系统以进行干净还原，请参见 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-clean-restore.html["创建隔离的恢复环境"^]。要了解如何使用干净还原进行恢复，请参见 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-clean-restore-recover.html["使用干净还原恢复工作负载"^]。

=== Cloud Volumes ONTAP



==== 借助 Google Cloud C3 VM 改进了 Cloud Volumes ONTAP 支持

Cloud Volumes ONTAP 现在增强了对 Google Cloud C3 系列虚拟机的支持，实现了以下附加功能：

* 在 Cloud Volumes ONTAP 部署中，您可以在 C3 系列中的不同变体之间切换实例类型。
* 更改实例类型时，如果选择 c3-standard-44 或 c3-standard-88 及其 LSSD 变体作为目标 VM，则会自动应用 Google 网络服务出口网络层 Tier-1。如果切换到任何其他 C3 变体，则出口网络层设置为 Standard。
+

NOTE: 将出口网络层更改为 Tier-1 会产生额外费用。相应地规划部署和升级。

* 如果您选择 C3 的本地 SSD (LSSD) 变体，默认情况下会启用 Flash Cache。无法在 Cloud Volumes ONTAP 部署中的 C3 LSSD 变体之间切换，即使目标变体支持 Flash Cache。
* 现在，您可以在 C3 虚拟机上向新的和现有的聚合添加卷。
* 通过 NetApp Console 或使用 `PUT /gcp/vsa/aggregates/{workingEnvironmentId}/{aggregateName}` API 添加卷时，可以更改 IOPS 和吞吐量设置。
