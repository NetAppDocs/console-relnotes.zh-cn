=== 备份和恢复



==== Kubernetes 工作负载增强功能

在本版本中，NetApp Backup and Recovery 为 Kubernetes 工作负载引入了以下增强功能：

* *Trident Protect 26.10*：此版本包括 Trident Protect 26.10。
* *ontap-nas-economy 和 ontap-san-economy 驱动程序支持*：您现在可以保护由 NetApp Trident `ontap-nas-economy` 驱动程序（Qtrees）和 `ontap-san-economy` 驱动程序（LUNs）配置的持久卷声明（PVCs）。当您使用 economy 驱动程序保护 PVC 时，整个底层 FlexVol 或 LUN 都会受到保护。您可以从这些备份还原单个 PVC。
* *Kubernetes 感知警报*：警报现在每个 Kubernetes 应用程序发送一次，而不是每个卷发送一次。
* *卷组快照支持*：现在可以在定义 Kubernetes 应用程序时创建卷组。卷组使您能够以崩溃一致性集的形式为多个卷一起创建快照，从而确保组中所有卷的数据一致性。
* *S3 兼容的对象存储支持*：您现在可以通过添加备份目标凭据和配置保护策略，将 Kubernetes 应用程序资源和数据备份到 S3 兼容的对象存储中。


要了解有关保护 Kubernetes 工作负载的详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["了解如何通过 NetApp Backup and Recovery 保护 Kubernetes 工作负载"^]。



==== ONTAP Volumes 工作负载增强

在本版本中，NetApp Backup and Recovery 为 ONTAP 卷工作负载引入了以下增强功能：

* *保护报告*：NetApp Backup and Recovery 现在支持为 ONTAP 卷工作负载创建和下载扩展报告。
* *注销 ONTAP 系统时保留备份*：从 NetApp Backup and Recovery 注销 ONTAP 系统时，您现在可以选择丢弃以前备份的数据或保留这些数据以供恢复。NetApp Backup and Recovery 文档现在包含有关在系统注销后使用 ONTAP CLI 恢复保留数据的说明。


有关更多详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-backup-manage.html#unregister-netapp-backup-and-recovery-for-a-system["注销系统的备份和恢复"^]。

要了解有关保护 ONTAP Volumes 工作负载的详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["了解使用 NetApp Backup and Recovery 的 ONTAP 卷保护"^]。



==== Oracle Database 工作负载增强

在本版本中，NetApp Backup and Recovery 为 Oracle Database 工作负载引入了以下增强功能：

*还原到备用位置*：NetApp Backup and Recovery 现在支持将 Oracle 数据库还原到备用位置（不同的注册主机）。

要了解有关保护 Oracle Database 工作负载的详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-oracle-protect-overview.html["了解如何使用 NetApp Backup and Recovery 保护 Oracle 数据库工作负载"^]。

==== 增强的隔离恢复环境配置

Ransomware Resilience 现在提供增强的隔离恢复环境配置工作流程。新的工作流程明确并简化了为云或本地环境设置隔离恢复环境的流程。

有关详细信息，请参见link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-clean-restore.html["为干净还原创建隔离的恢复环境"^]。



==== 用于启用用户活动监控的增强型工作流程

Ransomware Resilience 改进了启用用户活动监控的工作流程。以前，每次在工作负载上启用带有用户活动监控的勒索软件保护策略时，Ransomware Resilience 都会测试数据收集器的连接。借助该更新，如果存储 VM 存在数据收集器且处于“正在运行”状态，则现在会跳过该检查，从而加快保护工作流程。

有关详细信息，请参见 link:link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-use-protect.html["保护工作负载"^]。



==== Google Cloud NetApp Volumes Flex 服务级别正式推出

Ransomware Resilience 中 Google Cloud NetApp Volumes 对 Flex 服务级别的支持现已全面推出（GA）。

=== Cloud Volumes ONTAP



==== Azure 中的 Cloud Volumes ONTAP 9.19.1

现在，您可以使用 NetApp Console 在 Azure 中部署和管理 Cloud Volumes ONTAP 9.19.1 的正式发布（GA）版本。

自 2026 年 8 月起，控制台已支持 AWS 和 Google Cloud 中的 Cloud Volumes ONTAP 9.19.1。

https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-new.html["Cloud Volumes ONTAP 9.19.1 发行说明"^]



==== 适用于 Cloud Volumes ONTAP 的 Azure 主机加密

从 Cloud Volumes ONTAP 9.19.1 GA 开始，对于满足先决条件的新 Azure 单节点和高可用性（HA）部署，默认情况下会在主机上启用 Azure 加密。此功能会在数据写入主机和从主机读取时，对托管 VM 的物理服务器上的数据进行加密，包括临时磁盘和相关的主机级缓存。

在 Azure 中部署 Cloud Volumes ONTAP 之前，请确认您的环境满足以下先决条件：

* 已为您的 Azure 订阅注册了 `EncryptionAtHost`功能。请参阅 https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli["Microsoft 文档：在主机上启用加密"^]。
* 所选 VM 实例类型支持在您的 Azure 区域的主机上进行加密。请参阅 https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli#finding-supported-vm-sizes["Microsoft 文档：查找支持的 VM 大小"^]。


请注意以下几点：

* 无需额外配置。
* 如果不满足这些先决条件，则不会为 Cloud Volumes ONTAP 部署启用主机上的 Azure 加密。
* 主机加密仅适用于 Azure，不适用于 AWS 或 Google Cloud。


Microsoft 文档： https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal["使用 Azure 门户通过主机加密启用端到端加密"^]



==== Azure 和 Google Cloud 中 Cloud Volumes ONTAP 集群上的后端网络加密

Cloud Volumes ONTAP 9.19.1 及更高版本支持 Azure 和 Google Cloud 中 HA 配置的后端群集网络加密。

启用集群网络加密可能会影响集群性能。在启用此功能之前，请谨慎操作，并验证您的环境是否可以承受额外的开销。

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enable-cluster-encryption.html["在 Cloud Volumes ONTAP 集群上启用后端网络加密"^]



==== 能够减少 Azure 计划维护期间的中断

在计划维护期间，Azure 可以短暂暂停 Cloud Volumes ONTAP HA 对中的虚拟机。ONTAP 可能会将暂停解释为节点中断，并将存储操作移至伙伴节点，然后在 VM 恢复时将其移回（接管和交还）。即使没有节点故障，此过程也可能中断活动的客户端连接。

使用 Cloud Volumes ONTAP 9.19.1 及更高版本，您可以启用一项可选设置，允许 HA 对在 Azure 计划维护冻结期间继续运行，而无需自动启动接管和交还。


NOTE: 此功能在 Cloud Volumes ONTAP 9.19.1 中作为公开预览版提供。

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-azure-prevent-freeze.html["防止在 Azure 维护期间 Cloud Volumes ONTAP HA 对发生中断"^]

==== Kubernetes 资源组的可选引导顺序

NetApp Disaster Recovery 现在支持通过指定资源的优先级顺序和可选的延迟时间，为 Kubernetes 复制计划中的资源组设置可选的启动顺序。此选项使您能够在必要时同时启动资源，并延迟启动依赖于其他资源的资源，从而支持您的应用程序以健康的方式恢复联机。

有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/task-replication-plan-kubernetes.html["创建复制计划"^]。

有关详细信息，请参见link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["故障转移"^]和link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failback.html["failback"^]的说明。



==== 简化刷新和合规运行

针对 vCenter、复制计划和法规遵从性的刷新运行已简化为单个作业，以加快执行速度。要查看此更改，请了解如何 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["监控作业"^]。



==== Kubernetes 合规性检查

灾难恢复添加了合规性检查，以识别 Kubernetes 工作负载缺少的工作环境。这些合规性检查有助于确保工作负载运行状况，以确保复制计划的完整性。

==== ONTAP Volumes 工作负载增强

在此版本中，ONTAP Volumes 工作负载引入了以下预览增强功能：

* *改进对暗站点的支持*：暗站点的 NetApp Backup and Recovery 现在提供与 NetApp Backup and Recovery 相同的 ONTAP Volumes 数据保护功能。此增强功能包括更新的备份、还原和作业管理服务以及新的元数据数据库。在升级期间，将自动保留和迁移现有数据库数据。升级后，请查看审核日志以验证迁移是否成功完成。暗站点的 NetApp Backup and Recovery 仅支持 ONTAP Volumes 工作负载。
* *取消卷还原作业*：您现在可以从作业监控页面取消正在进行的 ONTAP 卷还原作业，从而更轻松地管理长期运行或运行缓慢的作业。
* *改进的卷索引状态报告*：ONTAP 卷仪表板现在通过为不符合索引条件的卷和快照副本引入 `Not Applicable`状态，更准确地报告索引状态。该 `Not Indexed`状态现在专用于等待索引的卷，卷详细信息现在显示每个快照的索引状态，并附有悬停文本说明卷或快照副本不会被索引的原因。
* *NetApp AFX 支持*：您现在可以保护托管在 2 节点和 4 节点 NetApp AFX 集群上的卷。

* *支持 NetApp Console 本地部署*：此版本的 NetApp Backup and Recovery 支持处于预览状态的 NetApp Console 本地部署。
* *90 天的作业保留*：Backup and Recovery 现在会在 Job Monitor 中保留作业信息 90 天。




==== VMware 工作负载增强功能

在此版本中，VMware 工作负载引入了以下增强功能：

* *还原到备用位置支持（适用于 SAN VM）*：现在，您可以将基于 SAN 的 VM 备份还原到备用位置。
* *Multiple backup delete support*：您现在可以一次删除多个备份。


要了解有关保护 VMware 工作负载的详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-vmware-protect-overview.html["保护 VMware 工作负载概述"]。



==== Kubernetes 工作负载增强功能

在此版本中，Kubernetes 工作负载引入了以下增强功能：

* *预览对气隙资源的支持*：如果在 NetApp Console 本地部署中运行 NetApp Backup and Recovery，您可以发现、保护和还原气隙 Kubernetes 资源。此功能在此版本中处于预览状态。


要了解有关保护 Kubernetes 工作负载的详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["保护 Kubernetes 工作负载概述"]。



==== ONTAP Volumes 工作负载增强

在此版本中，ONTAP Volumes 工作负载引入了以下增强功能：

* *将还原作业优先于备份*：现在，在还原卷、文件或文件夹时，您可以将还原作业优先于备份作业。
* *在不激活 Backup and Recovery 的情况下发现 ONTAP 系统和卷*：您现在可以在不激活 Backup and Recovery 的情况下发现系统和卷。


要了解有关保护 ONTAP Volumes 工作负载的详细信息，请参阅 https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["保护 ONTAP 卷工作负载概述"]。

=== 数据分类



==== 活动扫描选项卡可增强扫描管理

数据分类现在在配置菜单中提供了 *Active scans* 选项卡，为管理扫描提供了增强的体验。Active scans 选项卡提供了您已激活扫描的所有卷的概述，并提供熟悉的筛选器以对资源进行排序。该选项卡还提供了一个集中位置，用于确定扫描优先级、暂停扫描和查看错误。

有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-data-classification/task-managing-repo-scanning.html["管理扫描"^]。



[[disaster-recovery]]
=== 灾难恢复



==== 改进的控制面板

已更新 Disaster Recovery 控制面板，提供增强的体验，让您一目了然地全面了解整个 Disaster Recovery 资产。全新控制面板包括：

* *统一工作负载可见性* — 从单一窗格监控 VMware 和 Kubernetes 工作负载以及底层基础设施的运行状况。
* *主动显示问题* — 控制面板现在自动突出显示环境问题，从而实现更快的诊断并缩短解决时间。
* *容量利用率* — 容量指标现在直接显示在仪表板中，从而更轻松地了解资源消耗情况。


有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/dashboard-view.html["在控制面板上查看 NetApp Disaster Recovery 计划的运行状况"^]。



==== 改进报告

报告功能已得到扩展，可以更深入地了解整个环境中的 Disaster Recovery 活动：

* 生成适用于 VMware 工作负载、Kubernetes 工作负载或两者的报告，让您可以灵活地为受众定制报告。
* 每个报告提供指定时间段的完整活动摘要，确保灾难恢复环境中的事件完全可见。


有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/reports.html["创建 NetApp Disaster Recovery 报告"^]。



==== 用户作业日志记录

Disaster Recovery 通过用户级作业日志记录提高了作业的可问责性和可审计性。现在，执行的每个作业都会记录发起该作业的用户，为合规性和故障排除目的提供清晰的审计跟踪。Disaster Recovery 自动触发的作业被标识为"system"，便于区分用户发起的活动和服务发起的活动。

有关详细信息，请参见 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["监控 NetApp Disaster Recovery 作业"^]。



==== 性能和资源优化

已进行了各种底层改进，以减少整体系统资源消耗并提高 Disaster Recovery 操作的性能。

NetApp Console 中精心设计的仪表板现在允许您修复 Cloud Volumes ONTAP 系统的配置建议。

您还可以从良好架构分析中忽略一个或多个配置。这样，您可以忽略不适用于您的环境的特定配置。
